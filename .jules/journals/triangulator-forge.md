 2026-04-27 - KV Cache and Scheduler Coupling in Modern Inference Engines
Learning: During a deep comparative audit of vLLM, TGI, and LMDeploy, a recurring architectural deception was identified: the tight coupling between the `Scheduler` and the `BlockSpaceManager` (or equivalent KV cache manager). Schedulers consistently contain deep knowledge of physical hardware blocks rather than abstract logical tokens. This framework entanglement makes injecting custom hardware quantization schemes (like RotorQuant `rq3_iso` or `rq4_planar` on ROCm) excessively difficult, requiring invasive core refactors rather than simple adapter insertions.
Action: Implement a strict abstraction boundary between the `Scheduler` and the `KVCacheManager` in `sglang-1-bit-turbo`. The scheduler must output purely logical block allocations (integer IDs), while the `KVCacheManager` independently handles physical memory allocation, hardware-specific data types, and Triton kernel integration.

2026-04-27 - Extensibility constraints of strict IPC boundaries
Learning: While rigid IPC boundaries (like TGI's Rust router via gRPC to Python execution) provide excellent operational stability, they create significant integration constraints when attempting to pass custom data payloads, such as those required for 1-bit quantization schemes or dynamic speculative decoding trees. The serialization overhead and schema rigidity of protobuf/gRPC can negate the performance benefits of lightweight hardware backends.
Action: For `sglang-1-bit-turbo`, when adopting a bounded service architecture, avoid heavy RPC protocols for the hot-path data exchange. Instead, prefer shared memory (shm) or highly optimized zero-copy protocols (like optimized ZMQ) to maintain the boundary without the serialization penalty.
